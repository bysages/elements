title: "Client Only"
description: "Render children on the client only, after hydration — the escape hatch for browser-only widgets inside server-rendered pages. Headless: no visual layer of our own."

---

A server-rendered page paints before the browser has spoken: `window` is
unreadable, canvases are unmeasured, and anything betting on them would
tear the hydration contract. `ClientOnly` holds its children back until
the client has mounted — the server renders the fallback instead, and
the two swap places in one piece, so the markup the server sent and the
markup Vue expects always agree.

Reach for it when a subtree cannot render on the server at all — a
canvas chart, a map, an editor — or when its first client-side measure
would otherwise disagree with the server's guess and flash.

## Basic usage

```vue
<script setup>
import { ClientOnly } from "@bysages/vue";
</script>

<template>
  <ClientOnly>
    <template #fallback>
      <p>Loading the chart…</p>
    </template>
    <BrowserChart />
  </ClientOnly>
</template>
```

The fallback renders on the server and stays until hydration completes;
the default slot then replaces it. Without a fallback the slot simply
stays empty until mount.

## Slots

| Slot | Description |
| --- | --- |
| `default` | The children, rendered on the client only — after hydration |
| `fallback` | What the server renders in the meantime, and what stays until mount |
